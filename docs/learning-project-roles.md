These two lessons extend the six-guide library without treating every task as the same tabular exercise. The public guides contain the bounded experiment plans and next actions:

- [Digit Recognizer](../src/content/competitions/competition-digit-recognizer.md): 28×28 / 784-pixel layout, label coverage, training-only class centroids and one per-image L2 change. The published script, notebook and receipt remain a runnable synthetic geometric-pattern fixture. The proposed authorized-data port is not executed or verified. It caps the declared prefix at 1000 images, freezes five stratified folds/seed 17, inspects per-class/confusion/blank-image aggregates and measures full-pipeline wall time and process RSS. Writer-held-out validity remains unknown.
- [Home Credit](../src/content/competitions/competition-home-credit-default-risk.md): customer-keyed validation, one-to-one application predictions and one family of prediction-time-safe history aggregates. This remains guide-only, with no learner baseline result or execution receipt. Its proposed port caps the scope at 10,000 application entities and 100,000 complete eligible history rows from one table, freezes five customer-level stratified folds/seed 17, and compares a fixed application-only logistic baseline with one prior-credit count. Key/time definitions and authorization must be verified before running. A verified application/loan key does not establish distinct-person identity; when cross-application customer mapping is unknown, report application-keyed validation and leave person-held-out validity unknown. Historical reported AUC is never an expected learner score.

Both access/preparation owners are explicitly unassigned maintainers. Their next action is to establish authorized local inputs and validate the declared schema, key/time assumptions and reporting rights, then implement a pinned shared-script/notebook package and safe actual-data receipt. These plans do not authorize data downloads, publication of restricted data or Kaggle submissions. No neural model, winning relational system, target-derived history feature or historical reproduction is required.

Keep metrics that worsen, undefined metrics, malformed inputs and access/cutoff failures explicit. Only successful actual-data execution with inspected provenance and the [closed receipt contract](content-model.md#learning-project-readiness-incremental-version-1-extension) can establish actual-data verified readiness. Raw pixels, customer keys, labels and split assignments remain private; permitted public diagnostic summaries carry aggregate counts and fingerprints. Runtime, total process memory and completion time are unknown until measured for that exact scope.

The existing Digit CSV runner emits normalized rows into a local data artifact and uses `reader-provided-data`; neither that label nor the raw artifact satisfies the publication contract. A future adapter must construct safe fingerprint-only inputs and closed diagnostic summaries. Source solution compute remains separate from any measured learner-project budget.
