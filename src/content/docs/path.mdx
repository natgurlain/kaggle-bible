Start with Titanic, then House Prices, then Disaster Tweets. The labels below show which published projects you can start now and which still need preparation. A runnable label means you can start that recorded project now. Generated teaching fixtures teach a controlled workflow and do not establish performance on competition data; an actual-data verified label covers only its reviewed input and evaluation scope.

Advance when you can rerun the baseline and one change on unchanged validation, inspect their differences and explain a limitation. A negative or worse result is valid evidence. A leaderboard position, metric improvement or clicking a completion button is not the gate. Keep your own notes; this path has no login or saved progress.

## Optional future study

[Home Credit](/competitions/home-credit-default-risk/) is a published guide to customer-keyed validation and relational aggregation. It is guide-only: there is no published learner project or measured learner baseline. Read its bounded next-experiment plan after the core loop; establish authorized access and key/time semantics before preparing a runnable port.

[LMSYS Chatbot Arena](/competitions/lmsys-chatbot-arena/) is a published evidence map for an LLM-era preference task. It covers response-order symmetry, prompt-grouped validation and the gap between inference and training compute. It is guide-only: there is no learner project, and the source solutions trained on multi-GPU A100 machines. Read it after the core loop as a map of documented approaches, not as a runnable lesson.

Choose future study for the next decision you need to learn. Compare independent source accounts and state what depends on that competition's data and validation before transferring an idea. Historical source scores and hardware remain separate from your own baseline, resources and learning evidence.

## Keep a small experiment record

Record the target and metric, authorized input scope or fixture label, fixed split and seed, package/environment, baseline and one change, per-split results, diagnostics and limits. Explain why a change helped, hurt or remains inconclusive before choosing another experiment. [Validation checks](/practices/validation-checks/) and [compute planning](/practices/compute-resource-planning/) help with that explanation; the [project pages](/exercises/) provide pinned scripts, notebooks, fixture receipts and recovery steps.
